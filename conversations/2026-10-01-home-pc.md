## 1. 집 PC 첫 실행과 수정
- 설치: .NET 10 SDK·Node LTS(winget), NINA·Advanced API·ASCOM(사용자)
- 울트라와이드에서 깨진 곳: 새 프로필 요소가 세로로 벌어짐, 선택 쉐브론이 옆 칸을 덮음, 장비 변경 모드 원이 한 줄로 몰림, 다시 연결 실패 뒤 가운데 문장 사라짐(버그) → 모두 수정
- 장비 "무조건 연결 성공"은 시뮬레이션이라 그런 것. 실제 연결 경로는 `$env:Equipment__Simulate="false"`로 NINA 시뮬레이터 장비를 써서 시험 가능
- NINA는 드롭다운에서 고르기만 하면 프로필에 저장되지 않고, 연결 버튼을 한 번 눌러야 저장되는 것으로 보임

## 2. 화면 크기 (사용자 결정)
- **기준 화면 1920×1080** = 사용자 4K 노트북을 배율 200%로 쓸 때의 크기. 앱을 이 크기로 그린 뒤 창에 맞춰 통째로 확대·축소
  - → 뒤에 바로잡음: 노트북은 3840×2400(16:10)이라 200%면 1920×1200. 기준 화면을 1920×1200으로 바꿈 ([2026-10-01-work-laptop.md](2026-10-01-work-laptop.md))
- 울트라와이드는 좌우로 늘리지 않고 16:9만큼 가운데, 나머지는 여백
- 화면 안의 크기는 `vw`·`vh` 대신 틀 기준 `cqw`·`cqh`
- 상태 줄은 위, 단계 레일은 아래 유지 (옆 세로 배치는 계획 화면·폰과 부딪힘)

## 3. 관측지 (사용자 설계, 구현함)
- 기준은 AA(프로필마다 관측지 목록 최대 10개), N.I.N.A.는 따라감. 앱 시작·계획은 온라인 필수라 카카오맵 사용
- 장비 연결 완료 막대 위 "현재 관측지는 위도 …° · 경도 …° (이름)입니다" + 변경. 없으면 강제로 관측지 고르기. 막대를 가리키면 멈춤. 장비 변경·변경 완료 버튼은 가운데 원 안으로
- 관측지 고르기: 제목 왼쪽 뒤로 버튼(둥근 사각 + <), 카드 5×2(추가가 맨 앞), **두 번 눌러 설정**(카드가 뒤집혀 안내), 이름만 수정(좌표 수정 취소), 위도·경도 칸 분리, 휴지통 + 되돌리기, 오른쪽 정보에 빛이 훑고 지나가는 효과
- 상태 줄: 관측지 이름·좌표·연필(목록에서 고르기만, 관측지 편집으로 이동). 저장 안 된 장소는 "(저장 안 됨)" + 점선 칸 + 디스크
- 프로필 사진: 누르면 다른 프로필이 아래로 펼쳐지고 바로 전환. 편집(별명·메모·사진)은 앱 시작 때 프로필 선택 화면의 연필
- 모달: "모달 위에 모달"만 금지로 완화
- NINA 위치 쓰기 확인: `profile/change-value?settingpath=AstrometrySettings-Latitude` 형식 동작 (`.` 형식은 실패)

## 4. 경통 (사용자 설계, 구현함)
- 경통은 연결 장비가 아니라 NINA도 모름 → AA 경통 목록(프로필과 무관, AA 전체), 수동 입력(표준 데이터가 없어서)
- 이름 · 초점거리 · 구경 또는 F값 · 리듀서/플래트너 배율(선택). 장비 연결 화면에 "경통" 원(필수), 장비 변경 모드에서 목록 관리
- 사용자 장비: **Pleiades 68 (260mm F/3.8 펫츠발)**, **삼양 12mm F/2.0** — 데이터 폴더 optics.json에 넣어 둠. NINA 망원경 설정도 Pleiades 68로 써짐

## 5. 그 밖
- 앱 아이콘: 사용자가 준 `AstrophotoAssistant.png`(500×500) → 16~256px .ico, 브라우저 탭 아이콘도. 색이 푸른 계열이라 앱 분위기와 안 맞지만 지금은 두기로
- 스트링 테이블: 지금은 불필요 (한국어 하나, 문구가 계속 바뀜)
- 장비 연결로 넘어갈 때 원: 1단계 완료 원 → 진행 중 원 크로스페이드, 글자는 옛 글자가 먼저 사라진 뒤 새 글자(겹침 없음), 10% 빠르게

## 6. 모핑 효과 제안 (다음에 결정·구현)
화면 요소가 사라지고 나타나는 대신 같은 요소가 모양·크기·자리를 바꾸며 이어지는 것. 글자끼리는 뭉개져 보여서 피하고, 촬영 중에는 움직임 최소.
1. **(추천) 프로필 사진 → 상태 줄 프로필 사진**: 고른 사진이 작아지며 왼쪽 위 자리로
2. 설치 확인 쉐브론 → 엔진 켜기 원: 다섯 칸이 가운데로 모이며 원으로
3. **(추천) 단계 레일 현재 표시**: 점이 다음 단계로 미끄러지고 게이지 선이 차오름
4. 자비스 원 진행 중 → 완료: 돌던 호들이 길어져 닫힌 원으로
5. 장비 원 → 변경 모드 아이콘 원: 제자리에서 줄며 아이콘으로 (지금의 흡수·펼침은 사용자 설계라 비교용)
6. 관측지 카드 → 오른쪽 정보 칸 (이미 뒤집기·빛 효과가 있어 과할 수 있음)

## 7. 저녁 이어서 (회사 작업 확인 뒤, 집 PC)

**준비 화면 다시 생각하기**
- 시안 1: 왼쪽 진행 목록 + 오른쪽 작업 영역(Codex CX-PREP-UI 방향) → `mockups/aa-prepare.html`. 사용자: 실제로 보니 마음에 안 듦. 준비는 열어 두고 지켜보는 화면이 아니라 **지나가는 절차**라서 **한 화면 = 목표 하나**(윈도우 첫 설치처럼)가 맞다
- 시안 2: 1단계(극축정렬)만 한 줄기 구성(진행 표시 → 큰 제목 → 할 일 카드 → 상태 한 줄 → 가운데 큰 버튼 → 자세히) → `mockups/aa-prepare-step.html`. 사용자: 이것도 상상하던 모습은 아님 → **사용자가 더 고민하기로** (화면 구성 미정)
- 정해 둘 틀(제안): 진행 표시·제목·주 버튼은 고정, **가운데 주인공 칸은 단계마다 크기가 다름**(할 일 카드 / 자비스 원 / 초점 곡선 / 가이딩 그래프 / 시험 사진 / 나중에 극축정렬 실시간)
- Codex 리뷰(왼쪽 목록)와 방향이 달라지면 REVIEW_CODEX.md에 이유를 기록할 것

**극축정렬 조사**
- 카메라는 한 프로그램만 잡을 수 있음 → ①에서 PHD2가 가이드 카메라를 놓고 SharpCap에 넘김, ②에서 다시 PHD2. SharpCap에서는 적도의를 연결하지 않도록 안내할 것. ① 동안 상태 줄 PHD2 점에 "SharpCap 사용 중" 같은 이유 표시
- SharpCap: 외부 API 없음(개발자 포럼 답변), 공식 스크립트 문서에도 극축정렬 값 없음. 내부 분석으로 꺼내는 건 가능성 있음(.NET + IronPython이 같은 프로그램 안에서 돔)
- NINA TPPA: 사진 → 솔빙 반복이라 몇 초에 한 번 갱신. Advanced API TPPA 채널로 값을 받을 수 있음(미확인). NINA의 "카메라" 칸 카메라로 동작 → X-T5면 넘겨주기는 없지만 느릴 수 있음, 가이드 카메라로 하려면 NINA 카메라·초점거리 설정을 바꿨다 되돌려야 함
- 결정: 지금은 **SharpCap 안내 방식**. TPPA는 회사 노트북에서 X-T5 갱신 속도를 시험한 뒤 판단

**자비스 비서 컨셉 (사용자 구상 → Claude 움직이는 시안 `mockups/aa-prepare-jarvis.html`)**
- 가운데 자비스 원 + 단계 원(장비 연결 화면과 같은 말투), 지금 단계로 전류 → 카메라가 다가가 원이 자비스 원의 150% → 숫자가 단계 이름으로 크로스 디졸브 → 호 카드(세부 과정)
- 정한 것: **② 가이드 연결을 ① 극축 정렬 안에 합쳐 전체 6단계**(극축 정렬 · 대상 이동 · 초점 · 센터링 · 가이딩 · 시험 사진). ① 안의 세부: SharpCap 실행 → 정렬 확인("완료했어요", 사용자가 누름) → PHD2 재연결(SharpCap이 열려 있어 실패하면 다시 시도)
- 지금 호가 항상 가운데(오른쪽 안내를 향함), 끝난 호는 반시계로 밀려나고 다음 호가 가로로 펼쳐짐, 글자는 가로
- 완료 표시: 숫자가 사라지고 **체크가 선으로 그려짐 + 느린 빛 한 바퀴**(도는 호 = 작업 중이라 완료는 계속 돌지 않음). 가리키면 숫자와 단계 이름 툴팁. "PASS 도장"은 아날로그라 취소
- **준비 중단**: 준비·촬영 공통 → 하단 레일 오른쪽 앱 끄기 왼쪽. 준비·촬영 단계에서만 보이고, 누르면 한 번 더 묻기
