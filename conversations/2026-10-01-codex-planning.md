## 1. 사용자 설명과 상담 범위

- 촬영 계획 단계는 목업 시안과 초기 구현이 있고, 앞으로 수정해 나갈 시점이다.
- 현재 구상은 AI 대화로 **촬영 대상 → 구도 → 촬영 설정 → 끝난 뒤**를 정한 뒤 준비 단계로 진행하는 것이다.
- 대화로 정한 내용을 Advanced API를 통해 N.I.N.A.에 전달하려 한다.
- 사용자는 시퀀스에 추가로 필요한 내용, 불필요한 질문, 보유·연결 장비에 따른 질문 생략 여부를 물었다.
- 첨부 화면에는 대상 추천, 가운데 배치, 필터 선택, 노출·ISO 추천, 종료 조건 및 파킹·연결 해제 요약이 있었다. 화면의 예시 값은 사용자의 확정된 촬영 계획이나 실제 장비 설정으로 취급하지 않는다.

## 2. 장비별 질문과 시퀀스 구성 (Codex 제안, 미확정)

- 네 카드 구성은 유지할 수 있다. 사용자의 의도가 필요한 부분만 질문하고, 프로필·장비 정보와 기존 정책으로 알 수 있는 항목은 자동으로 채운다.
- 장비 기능은 단순 연결 여부 외에 **자동 가능 / 수동 가능 / 사용 안 함 / 미확인**을 구분하는 방향을 제안했다.
- 이번 촬영에 쓰지 않는 장비와, 원래 필요한데 일시적으로 연결이 끊긴 장비는 구분한다. 후자의 기능을 조용히 삭제하지 않는다.
- 필터휠이 없어도 수동 장착 필터가 있을 수 있다. 자동 교체 질문은 생략하되 장착 필터 정보는 필요하다.
- 전동 포커서가 없으면 자동 초점 주기 질문을 생략하고 준비 단계의 수동 초점 확인으로 연결한다.
- 냉각 기능이 없으면 목표 온도·워밍을 생략한다. 가이딩을 쓰지 않으면 가이더 기반 디더링·복구를 그대로 넣지 않는다.
- 자동 플랫 패널·커버가 없으면 자동 보정 촬영을 당연한 기본값으로 넣지 않는다. 수동·스카이 플랫이나 수동 차광은 사용자의 개입 가능 여부에 따라 별도로 다룬다.
- 전원 제어 기능이 없으면 자동 전원 끄기를 제안하지 않는다. 장비 연결 해제와 전원 종료는 다른 동작이다.
- 촬영 중 사람이 직접 장비를 만질 수 있는지 알아두면 수동 회전·필터 교체·차광 등을 계획에 넣을 수 있는지 판단할 수 있다.

## 3. 로테이터가 없어도 구도 설정은 의미가 있음 (설명하고 사용자가 이해를 확인한 개념)

사용자는 “대상을 중앙으로 둘 때 x:y로 GoTo하고, 오른쪽에 놓으려면 x1:y1로 조정할 수 있으니 의미가 있다는 것이냐”고 확인했고, Codex는 그렇다고 설명했다.

- **화면 중심 위치 변경**과 **카메라 회전**은 별개다.
- 대상의 천구 좌표와 실제 촬영 중심 좌표를 구분하면, 로테이터 없이도 마운트 지향을 바꿔 대상을 화면 오른쪽 등에 배치할 수 있다.
- 화면의 오른쪽이 하늘의 어느 방향인지는 현재 카메라 방향과 화각에 달려 있다. 단순히 RA에 고정값을 더하는 방식으로 일반화하지 않는다.
- 전동 로테이터가 없을 때는 현재 방향 유지가 기본값이 될 수 있다. 사용자가 원할 때만 수동 회전 경로를 제시하는 방향을 제안했다.
- N.I.N.A. Manual Rotator는 솔빙 결과에 따라 사람이 돌릴 방향·각도를 안내하는 기능이다. 전동 로테이터가 없다고 수동 회전까지 불가능한 것은 아니다.
- 현재 방향이 미확인이면 임의의 0°를 확정값처럼 표시하지 않고 준비 단계에서 확인할 수 있다.
- 데이터에서는 **회전하지 않음**과 **0°로 회전**을 구분해야 한다는 제안이 있었다.

## 4. 추가로 정할 내용과 줄일 질문 (Codex 제안, 미확정)

- 촬영 시간 제약을 대상 추천 전에 반영한다. 시작 가능 시각, 종료 시각, 목표 장수 또는 총 노출 시간, 고도·지평선·박명 제한의 우선순위를 계획에 표현한다.
- 종료 시각이 마지막 촬영 종료인지 파킹 완료인지 구분한다. 이를 모두 별도 질문으로 묻기보다 사용자의 시간 의도를 받아 정책으로 풀어낸다.
- 디더링, 자동 초점 조건, 자오선 반전, 중심 이탈 보정, 가이딩 복구, 오류 시 대기·재시도·종료는 장비 구성별 정책·템플릿으로 두고 매번 대화로 묻지 않는 방향을 제안했다.
- 가운데 배치는 기본값으로 제시하고, 대상이 잘리거나 주변 천체를 함께 담는 등 의미 있는 선택일 때 질문한다.
- 필터 선택지는 보유·장착 정보를 반영한다. 이미 알고 있으면 반복해서 묻지 않는다.
- 달 밝기만으로 노출·ISO를 정한다고 설명하지 않는다. 카메라·광학계·필터·추적 조건을 반영한 초기 추천값을 준비 단계의 시험 촬영으로 검증하는 방향을 제안했다.
- 예상 장수에는 다운로드·디더링·초점·반전 등의 시간을 고려한다. 시간 제한 계획에서 예상 장수를 별도의 필수 달성 목표로 바꾸지 않는다.
- 카드 상태는 사용자 응답 여부만으로 ‘정해짐’ 처리하기보다 추천 적용 / 사용자 지정 / 준비 중 확인을 구분하는 방향을 제안했다.

## 5. 예상 화각에 필요한 사전 정보 (사용자 질문과 Codex 설명)

사용자는 경통에 따라 예상 화각이 달라지고, N.I.N.A.에서 미리 확인한 뒤 GoTo·촬영·플레이트 솔빙을 했던 경험을 설명하며 사전 입력의 필요성을 물었다.

- 예상 화각에는 **유효 초점거리와 센서 가로·세로 크기**가 핵심이다. 센서 크기는 픽셀 크기와 가로·세로 픽셀 수로도 구할 수 있다.
- 경통 모델명만으로 충분하지 않다. 리듀서·바로우·카메라를 포함한 실제 촬영 조합을 알아야 한다.
- 명목 초점거리와 배율 적용 후 유효 초점거리를 구분해 배율을 중복 적용하지 않는다.
- 카메라의 현재 방향은 준비 단계의 솔빙으로 확인할 수 있다. 이전 촬영 값을 참고하더라도 카메라 재장착·회전으로 달라질 수 있으므로 확정값으로 취급하지 않는다.
- 제안한 흐름: **연결 단계에서 정보 확보 → 계획 단계에서 예상 화각·구도 활용 → 준비 단계에서 시험 촬영과 솔빙으로 실제 중심·방향·이미지 스케일 확인**.
- 가져올 수 있는 값은 자동으로 읽고, 부족한 필수 값만 최초 입력받는다. 촬영 계획 대화마다 같은 장비 정보를 재입력하게 하지 않는다.
- 광학 조합별 설정을 관리하면 ‘오늘 보이는 대상’뿐 아니라 ‘지금 장비에 잘 담기는 대상’을 추천할 수 있다.

### 같은 날 Claude 구현과의 관계

이 상담 중 일반론으로 ‘N.I.N.A. 프로필에서 읽고 부족한 값을 입력’하는 방식을 설명했지만, 기록 시 확인한 Claude 최신 작업에는 이미 **AA 경통 목록과 선택한 광학 정보를 N.I.N.A.에 쓰는 흐름**이 있다. 이를 되돌리거나 N.I.N.A.를 모든 광학 정보의 원본으로 바꾸라는 결정은 없다.

같은 날 Claude 기록에는 `OpticsStore`, 경통 선택, 배율 계산, N.I.N.A. 초점거리·F값·이름 쓰기가 정리되어 있다. 이후 구현 시 이 기존 흐름을 먼저 확인하고, 센서 정보·화각·솔빙 결과 활용 중 부족한 부분을 연결해야 한다. 이 문서 작성 과정에서 실제 구현의 완성도나 API 필드 전체를 검증한 것은 아니다.

## 6. Advanced API 전달 구조 (Codex 제안, 미확정)

**대화로 의도 결정 → 구조화된 계획 → 장비·시간·지원 기능 검증 → 검증된 템플릿에 적용 → N.I.N.A. 로드**를 제안했다.

- 자연어 응답만으로 실행 가능하다고 판단하지 않는다. UI에서 숨긴 미지원 기능은 생성 시퀀스에서도 제외한다.
- ‘필터 없음’과 ‘필터 미확인’, ‘회전 없음’과 ‘회전각 0°’처럼 실행 의미가 다른 값을 구분한다.
- [api-coverage.md](../api-coverage.md)의 템플릿 로드·대상 설정 방향을 참고했다. 해당 문서에 남은 시퀀스 세부 수정·JSON 로드 확인 과제를 해결했다고 주장하지 않는다.
- 실제 장비 검증은 이후 일괄 수행하는 현재 개발 단계를 유지한다. 이번 상담은 코드 리뷰나 구현 완료 판정이 아니다.
