# 사전 점검 설계 — N.I.N.A.가 오류를 내기 전에 아이라가 먼저 확인하기

작성: 2026-10-09 [Claude]. 바탕: [docs/codex/AIRA_ERROR_VERIFICATION.md](codex/AIRA_ERROR_VERIFICATION.md)(Codex 검증 목록 — 표의 ID는 그 문서의 ID), N.I.N.A. 로그 10/01~10/09 빈도, 2026-10-09 낮 실장비 읽기 조사.

## 1. 목표와 범위

- 사용자 요청(2026-10-09): N.I.N.A.의 오류·경고 토스트가 뜨는 상황을 **미리** 확인해 아이라 안에서 막거나, 알리거나, 준비시킨 뒤 진행한다. 오류가 난 뒤 풀어 쓰는 것(`Engine/NinaNotices`)은 그다음 방어선이다.
- **범위 밖:** 하드웨어 고장 자체(케이블 단선, 전원 고장)는 아이라가 고칠 수 없다. 다만 그 **상태를 미리 알아채 안내하는 것**은 범위 안이다(예: "카메라가 PC에 보이지 않습니다").
- 고장을 일부러 만들어 시험하지 않는다(Codex 4장). 실패 응답은 가짜 응답·로그로 시험한다.

## 2. 원칙

1. 확인 결과는 **정상 / 문제 / 모름** 셋. 조회 실패·없는 값은 정상이 아니라 "모름"(Codex 1장).
2. 관측한 사실과 가능한 원인을 나눈다. "USB 장치를 찾지 못함"은 사실, "전원이 꺼짐"은 후보.
3. 대응은 넷 중 하나로 정한다: **자동 해결**(아이라가 고칠 수 있고 안전함) / **준비시키기**(사용자가 할 일 한 줄 + 다시 확인) / **막기**(진행하면 위험·무의미) / **알리고 진행**(선택 장비).
4. 명령 뒤에는 결과를 다시 읽어 확인한다. N.I.N.A.가 "성공"이라고 답해도 실제로 안 된 사례가 있다(4장 S3).
5. 사용자가 손대야 하는 것은 한 번에 하나씩, 고치면 그 항목만 다시 확인한다(장비 연결 화면의 원과 같은 방식).

## 5. 실장비 조사 기록 (2026-10-09 낮)

- **S1 Empire 재연결:** 허브 USB를 다시 꽂은 뒤, 이미 켜져 있던 Empire는 허브와 연결되지 않았다 → N.I.N.A. 스위치 연결이 2분 기다린 뒤 실패("An error occurred while WandererEmpire was connecting"). Empire를 닫은 뒤 N.I.N.A. 스위치 연결을 하자 Empire가 새로 켜져 **16초 만에 자동 연결**.
- **S2 카메라 전원:** 더미 배터리 어댑터 입력이 **7~8.4V**인데 처음엔 DC4-6(허브 입력 그대로, 약 12.1V)에 꽂아 켜지지 않았다(약 3분 12V 인가 후 끔). 사용자가 적도의를 DC4로 옮기고 DC2(조절식)를 Empire에서 8.0V로 맞춘 뒤 꽂자 X-T5가 USB에 나타남: **WPD "X-T5", USB\VID_04CB&PID_02FC**. 사용자는 평소 배터리를 쓰기로 함.
- **S4 적도의 전원 = COM3:** 적도의 전원이 꺼지면 CP210x(COM3)가 목록에서 사라지고, DC4-6을 켜자 바로 나타났다(적도의 입력 12~24V, DC4 약 12.1V로 N.I.N.A. 연결·상태 읽기 정상). → "COM3 없음"은 적도의 전원 후보로 안내할 수 있다.
- **S3 출력 바꾸기:** N.I.N.A. `equipment/switch/set?index=`의 index는 출력 Id가 아니라 **쓰기 가능한 출력 목록의 순서(0부터)**. Id 3을 넣자 N.I.N.A.는 "Switch value updated"(성공)라고 답했지만 로그는 "No switch found for index 3", 값은 그대로. → 바꾼 뒤 반드시 다시 읽는다(Codex J04 실제 사례). 10/08 이전 로그의 같은 오류도 Claude 시험에서 같은 실수로 생긴 것으로 보임.
- 장치 식별: 위 4장 표의 ✅ 칸. 블루투스 직렬 포트(COM9·COM10)는 장비가 아니다 — 포트 목록에서 USB 장치만 본다.

- **S5 1차 구현 실기(14:30):** 시험 서버로 장비 연결 — 허브·적도의·포커서 정상, 카메라(꺼짐)는 아이라가 연결 전에 "카메라가 PC에 보이지 않습니다"로 막아 N.I.N.A. 오류 없음(로그 확인). 가이더는 PHD2가 "선택한 ToupTek 카메라를 찾을 수 없습니다" — USB를 다시 꽂아 PHD2가 기억한 카메라 정보가 바뀜. PHD2에는 카메라를 고르는 RPC가 없어 자동 해결 불가 → 장비 연결 창에서 다시 고르기 안내(있음). 다음 후보: PHD2 Alert 문장을 받아 이 원인을 정확히 짚기.
