## 0. 왜 다시 정리하나 (사용자 피드백)

- 쉐브론 모양이 설치 확인 화면과 같아 식상하다.
- "○○ 중입니다"만 나오고 안에서 뚝딱뚝딱 진행돼 **피드백이 너무 없다.** 문장을 더 쪼개 달라는 게 아니라, **장비가 실제로 보고 있는 것**(예: PHD2가 가이드 별을 잡는 모습)을 보고 싶다.
- 방향: 단계마다 **실시간 영상·그래프 + 목표를 향해 줄어드는 숫자 하나**. 문장은 짧게(지금 하는 일 한 줄).

## 1. 화면 전체에 늘 있어야 하는 것

| 요소 | 내용 |
|---|---|
| 단계 진행 | 7단계 이름, 각 상태(대기 / 진행 중 / 사용자 차례 / 완료 / 실패 / 건너뜀), 지금 단계 |
| 끝난 단계의 결과 한 줄 | 단계마다 아래 "결과 한 줄". 나중에 문제가 생기면 앞 결과를 보고 싶어진다 |
| 지금 단계의 큰 영역 | 실시간 영상·그래프 (아래 "실시간으로 보여 줄 것"). 화면의 주인공 |
| 지금 하는 일 한 줄 | 예: "자동초점 중입니다 (7/9)". 상태에 따라 색·아이콘 |
| 목표 숫자 | 단계마다 하나 (남은 거리, 별 크기, 오차, 가이딩 오차) |
| 버튼 | 단계마다 다름. 주 버튼은 하나. 실패 시 "다시 시도"는 늘 같은 자리 |
| 계획 요약 | 대상 이름 · 노출 × 예상 장수 · 종료 시각 (계획에서 확정한 값, 바뀌지 않음) |
| 경과 시간 | 준비를 시작한 뒤 흐른 시간 (지금 단계 경과도) |
| 오류 줄 | 버튼을 눌렀는데 처리할 수 없을 때의 이유 (자리 확보) |

화면 전체 규칙(DESIGN.md): 상태가 바뀌어도 다른 요소가 움직이지 않게 자리를 먼저 확보, 둥근 모서리, 토큰 색만, 촬영(적색) 테마에서 밝은 면 금지, 상단 상태 줄·하단 단계 레일은 그대로.

## 2. 단계별

표기: **자동** = AA가 진행, **사용자** = 사용자가 해야 넘어감. "출처"의 확인 상태 — ✅ 확인함 / 🔍 API에 있으나 아직 확인 안 함 / — 해당 없음.

### ① 극축정렬 — 사용자 (SharpCap)

- **목적**: 가이드 카메라·가이드 망원경으로 적도의 회전축을 북극에 맞춘다
- **시작**: "이 계획으로 준비 시작"을 누르면 바로
- **AA가 하는 일**: PHD2가 가이드 카메라를 놓게 함 → SharpCap 실행 (못 찾으면 직접 열어 달라고 안내)
- **사용자 할 일**: SharpCap에서 카메라 연결 → (필요하면) 가이드 초점 → 극축정렬 → SharpCap 종료 → "극축정렬을 마쳤어요"
- **실시간으로 보여 줄 것**: SharpCap 화면은 가져올 수 없다. 대신 할 일 순서(짧은 체크 형태), SharpCap 상태(열림 / 닫힘), 경과 시간
- **목표 숫자**: 없음
- **성공**: "마쳤어요" + SharpCap 종료 (순서 무관). AA가 오차를 잰 것이 아니므로 "사용자 확인"으로만 표시
- **결과 한 줄**: "사용자 확인 · 12분"
- **실패·예외**: PHD2가 카메라를 놓지 못함(다시 시도) / SharpCap만 닫히고 확인 없음("극축정렬을 마치셨나요?" + 마쳤어요 / SharpCap 다시 열기) / SharpCap을 못 엶(직접 열기 안내)
- **버튼**: 극축정렬을 마쳤어요(주) · SharpCap 다시 열기(닫혔을 때)

### ② 가이드 연결 — 자동

- **목적**: 가이드 카메라를 PHD2에 다시 연결
- **시작**: ① 성공 직후
- **AA가 하는 일**: PHD2에 장비 연결, 실패하면 몇 초 간격으로 3번까지
- **실시간으로 보여 줄 것**: 시도 횟수 정도 (몇 초면 끝남)
- **결과 한 줄**: "연결됨"
- **실패**: "가이드 카메라를 다시 연결하지 못했습니다" + 다시 시도 / PHD2 열기
- 가이딩을 쓰지 않으면 ②·⑥ 건너뜀

### ③ 대상 이동 — 사용자 승인 한 번 → 자동 (③~⑤ 이어서)

- **시작**: 사용자가 "대상으로 이동"을 누름. 누르기 전에 대상의 지금 고도를 본다
- **대상이 30° 아래면**: "M31 안드로메다는 지금 고도 15°로 아직 보이지 않습니다. 19:42쯤 30° 위로 올라옵니다" + 다시 확인. 멈춘다 (자동 대기·강행 없음)
- **AA가 하는 일**: 확정 계획의 좌표(J2000)로 이동만 (센터링은 ⑤)
- **실시간으로 보여 줄 것**: 하늘(또는 적경·적위 평면) 위에 **망원경이 가리키는 점이 대상 쪽으로 움직임**, 지금 고도·방위
- **목표 숫자**: 대상까지 남은 각거리 (예: 37° → 0.3°)
- **출처**: N.I.N.A. 적도의 위치 (Advanced API mount info) 🔍 — 이동 명령이 J2000을 받는지도 확인 필요
- **결과 한 줄**: "M31로 이동 · 고도 42°"
- **실패**: 시간 초과 / 이동 제한 / 연결 끊김 → 다시 시도
- **버튼**: 대상으로 이동(주) · 다시 확인(대상이 낮을 때)

### ④ 초점 — 자동 (포커서 없으면 사용자)

- **AA가 하는 일**: 대상 근처에서 N.I.N.A. 자동초점 한 번 (설정은 N.I.N.A. 값)
- **실시간으로 보여 줄 것**: **초점 곡선(V자) — 포커서 위치마다 별 크기 점이 하나씩 찍힘** + 방금 찍은 별 사진(작게)
- **목표 숫자**: 별 크기 HFR (작을수록 좋음), 진행 (7/9 지점)
- **출처**: N.I.N.A. 자동초점 진행·결과, 최근 사진 (Advanced API) 🔍
- **결과 한 줄**: "HFR 2.1 · 위치 12,340"
- **실패**: 별을 못 찾음 / 곡선 이상 → 다시 시도 / 손으로 맞췄어요
- **포커서 없음**: "초점을 손으로 맞춘 뒤 눌러 주세요" + 초점을 맞췄어요 (이때 짧은 노출 반복 사진이 있으면 도움 — 범위 미정)

### ⑤ 센터링 — 자동

- **AA가 하는 일**: 사진 → 솔빙 → 위치 보정 반복 (N.I.N.A.), **카메라 방향은 돌리지 않음**
- **실시간으로 보여 줄 것**: **솔빙에 쓴 사진 + 그 위에 대상 위치와 화면 중심 표시**, 반복할 때마다 갱신
- **목표 숫자**: 대상과 화면 중심의 오차 (예: 12′ → 2′ → 0.4′, 허용 범위는 N.I.N.A. 설정)
- **함께 알게 되는 것**: 지금 카메라 방향(각도) — 계획에서 "방향 유지"였으므로 정보로만 표시
- **출처**: N.I.N.A. 이동+센터링, 솔빙 결과, 사진 (Advanced API) 🔍
- **결과 한 줄**: "오차 0.4′ · 카메라 방향 87°"
- **실패**: 솔빙 실패(구름·초점·성도) → 다시 시도 / 초점 다시 맞추기 / 계획으로

### ⑥ 가이딩 — 자동 + 사용자 확정

- **AA가 하는 일**: 가이딩 시작 (별 선택·캘리브레이션은 PHD2), 캘리브레이션은 그날 밤 처음만, 안정되면 1~2분 오차 측정
- **진행 단계(화면에 구분)**: 별 고르는 중 → 캘리브레이션 중 → 안정되는 중 → 측정 중 → 판정
- **실시간으로 보여 줄 것**: **PHD2가 잡은 가이드 별의 확대 사진**(별 주변 작은 영역, 잡은 표시), **가이딩 그래프**(적경·적위 보정 오차가 시간에 따라)
- **목표 숫자**: 전체 가이딩 오차(″) vs 기준(주 카메라 한 픽셀, 지금 장비 약 2.4″)
- **판정**: 기준 이하·별 잃음 없음 = 충분해요 / 1.5배 이하 = 조금 더 지켜보세요 / 그 위 = 문제가 있어요. 측정값이 없으면 통과 금지. 인터넷이 되면 앱의 AI가 같은 수치로 설명 한두 문장을 덧붙임(판정은 바꾸지 않음)
- **출처**: PHD2 직접 API — 별 주변 사진(get_star_image), 보정 이벤트(GuideStep 등) 🔍 / N.I.N.A. guider info·graph 🔍
- **결과 한 줄**: "0.9″ (기준 2.4″) · 충분"
- **실패**: 별 없음 / 캘리브레이션 실패 / 별 잃음 / 안정 안 됨 — **구분해서** 안내 → 다시 시도 / PHD2 화면 열기
- **버튼**: 좋아요(주) · 다시 재기

### ⑦ 시험 사진 — 자동 촬영 + 사용자 확인 (항상 찍음)

- **AA가 하는 일**: 계획한 노출·ISO로 한 장
- **실시간으로 보여 줄 것**: 노출 진행(남은 초), 끝나면 **사진 크게** (확대해서 별 모양을 볼 수 있으면 좋음)
- **목표 숫자**: 별 수 · 별 크기 HFR (화질 판정은 아직 없음 — 숫자만)
- **출처**: N.I.N.A. 촬영·최근 사진 (Advanced API) 🔍
- **결과 한 줄**: "별 312개 · HFR 2.3"
- **버튼**: 촬영 시작(주) · 다시 찍기 · 다시 센터링

## 3. 단계 밖에서 생길 수 있는 일

- N.I.N.A.가 꺼지거나 응답 없음: 기존 공통 카드(NinaLostCard)가 화면 위에 뜬다
- 준비 중단 / 계획으로 돌아가기: 어디서든 가능해야 하는지, 어떤 단계부터만인지 미정
- 앱·화면을 다시 열면: 서버가 상태를 갖고 있어 하던 곳에서 이어짐 (같은 계획일 때)

## 5. 화면 구성 검토 때 정할 것

1. 단계 진행 표시의 모양 (세로 목록 제안 — 끝난 단계 결과 한 줄을 남길 수 있어서)
2. 큰 영역에 사진과 그래프를 동시에 보여 줄 때의 나눔 (⑥ 별 사진 + 그래프, ④ 곡선 + 사진)
3. 계획 요약·경과 시간의 자리
4. 준비 중단·계획으로 돌아가기의 자리와 허용 범위
5. 사진 확대 방법 (⑦)
6. 촬영(적색) 테마에서 사진·그래프를 어떻게 보여 줄지 (밝은 사진 자체가 눈부심)
