# AIRA 오류 예방·감지·복구 검증 목록

작성: 2026-10-09 [Codex]  
기준: HEAD a652971 + 현재 작업 트리의 N.I.N.A. 알림 처리 변경. 대상: OnStepX, X-T5, G3M662M/PHD2, Oasis, WandererBox/Empire, SharpCap, ASTAP.

## 1. 목적과 읽는 법

클로드가 N.I.N.A./Advanced API와 실제 장비에서 확인할 수 있도록 **120개 검증 시나리오**를 정리했다. 모두 실제 발생한 오류 또는 미수정 결함이라는 뜻은 아니다. 최신 HISTORY·현재 어댑터·알림 처리 코드에서 확인한 경로에 일반적인 실패 경계와 제안 테스트를 더한 목록이다. 이전 리뷰 18절의 지적은 이후 수정된 항목이 있으므로 이 문서를 근거로 미수정이라고 단정하지 않는다.

각 행의 ‘관찰’은 검증할 신호이며 해당 드라이버가 그 값을 제공한다는 보장이 아니다. **없는 필드·조회 실패·오래된 값은 정상(false/0)이 아니라 ‘미확인’**으로 취급한다.

검증 방식:
- **R**: 프로세스·설정·로그·장치 목록 및 의미상 읽기 전용 API 조회. 장비를 새로 연결하지 않는다.
- **F**: 가짜 HTTP/RPC·로그 재생·임시 파일·가짜 시계로 오류 주입. 위험한 실패를 실제 장비에 만들지 않는다.
- **S**: 별도 N.I.N.A./PHD2 시뮬레이터 프로필로 실행. 실제 장치가 섞이지 않았는지 먼저 확인한다.
- **H**: 실장비 연결·촬영·이동·정지 등 동작 검증. 하늘/장비 배치/사용자의 현재 작업을 확인한 전용 시험에서 수행한다.
- **U**: 사용자 육안 또는 프로그램 화면 확인. 자동 관측 수단을 확인하지 못한 항목.
- R/F 등 복수 표시는 먼저 읽기/가짜 검증 후 필요한 실기로 확장한다는 뜻이다.

응답 원칙:
1. 불가 조건을 확실히 알면 실행 전 막고 원인과 다음 행동을 안내한다.
2. 원인을 모르면 가능한 원인으로 표현한다. USB 미검출을 ‘전원이 꺼짐’, SDK open 실패를 ‘설정 창 점유’로 확정하지 않는다.
3. 명령 접수·진행·완료·정지 확인을 분리한다. 응답 누락 시 실제 실행 여부를 확인하기 전 명령을 재전송하지 않는다.
4. 자동 복구는 유한하며 정상 연결된 다른 장비를 함께 초기화하지 않는다.
5. 안전 상태를 모르는 장비는 새 이동·초점·노출 명령을 차단하고 재확인한다.
6. 경고를 번역해 띄우는 것과 작업 상태를 복구하는 것은 별개다. 토스트가 사라졌다고 오류가 해결된 것은 아니다.

## 2. 코드와 공식 문서에서 확인한 진단 수단

### N.I.N.A. / Advanced API

기본 베이스는 저장소 문서상 http://localhost:1888/v2/api 이지만 **설치된 실제 포트·버전을 먼저 확인**한다. GET이라도 연결·이동·촬영·종료를 수행하는 API가 있으므로 GET 전체를 읽기 전용으로 취급하지 않는다.

현재 코드/대응표에 있는 조회 후보:
- /version, /version/nina, /application/plugins
- /profile/show?active=true
- /equipment/info 및 /equipment/{camera,mount,focuser,guider,switch}/info
- /equipment/{kind}/list-devices: 드라이버 목록이지 물리 연결 증명은 아님. 플러그인에 따라 열거 시 초기화가 있을 수 있어 이후 확인.
- /event-history, /image-history?all=true
- /equipment/camera/capture/statistics, /equipment/focuser/last-af, /equipment/guider/graph

현재 NinaRig는 카메라 IsExposing, 적도의 Connected/Slewing/TrackingEnabled/AtHome/SideOfPier/Coordinates, 포커서 상태 등을 읽는다. 값의 이름·단위·미연결 응답은 설치 버전에서 저장해 확인한다.

공식 이벤트 문서에는 CAMERA-DOWNLOAD-TIMEOUT, ERROR-AF, ERROR-PLATESOLVE, AUTOFOCUS-POINT-ADDED, API-CAPTURE-FINISHED, IMAGE-SAVE 및 장비 연결 이벤트가 있다. **문서에 있다고 모든 실행 경로에서 발생하는 것은 아니다.** IMAGE-SAVE/완료 이벤트·조회·파일 존재를 함께 검증한다. 원본 토스트 전체를 제공하는 API라고 가정하지 않는다.
출처: [Advanced API 저장소](https://github.com/christian-photo/ninaAPI), [REST 문서](https://christian-photo.github.io/github-page/projects/ninaAPI/v2/doc/api), [이벤트 문서](https://github.com/christian-photo/ninaAPI/wiki/Websocket-V2). REST 문서는 동적 페이지여서 이번 조사에서 본문 전체를 추출하지 못했으며, 경로는 로컬 코드/대응표와 대조했다.

### PHD2 / Windows / 제조사 SDK

- PHD2 조회 후보: get_app_state, get_current_equipment, get_exposure, get_pixel_scale, get_calibrated, get_calibration_data. JSON-RPC 응답 id와 이벤트를 분리한다.
- 이벤트 후보: GuideStep, StarLost, SettleDone, Alert 및 연결/상태 이벤트. ErrorCode 의미는 설치 버전·원문과 함께 기록한다.
- Windows: 프로세스/실행 경로/PID, 현재 존재하는 PnP 장치·COM 포트·장치 식별자. 등록 이력과 현재 존재 여부를 구분한다. 점유 프로세스는 일반 장치 열거만으로 확정할 수 없다.
- Oasis: 현재 OasisSdk는 SetZero 전용이며 내부에서 Scan/Open/SetZero를 한다. **장치 검색 목적으로 SetZero를 호출하면 안 된다.** Scan만의 안전성·장치 식별·SDK ABI는 별도로 검증한다.
- Empire: 프로세스 실행과 허브 통신을 구분한다. 현재 코드상 센서 읽기도 드라이버 Connected=true를 만들 수 있으므로 ‘프로세스/파일만 읽기’와 동일한 무상태 작업은 아니다.

출처: [PHD2 RPC·이벤트](https://github.com/OpenPHDGuiding/phd2/wiki/EventMonitoring). 위 메서드 사용과 아래 복구 정책은 로컬 코드 및 이번 설계 제안을 함께 사용했다.

## 4. 클로드가 실행할 검증 순서

### 1차: 동작을 일으키지 않는 현재 상태 조사

1. 코드/문서 버전과 미커밋 변경을 먼저 기록한다. 기존 문서를 덮어쓰지 않는다.
2. 설치 경로·버전, 실행 프로세스/PID, NINA 활성 프로필, AIRA의 선택 장비, PHD2 장비 목록을 대조한다.
3. 이미 실행 중인 API만 조회한다. 조회 실패를 이유로 자동 connect/disconnect 또는 프로필 전환하지 않는다.
4. NINA 원본 로그를 source/method/level로 묶어 실제 원문 fixture를 만든다. 계정명·개인 경로·좌표는 공유본에서 가린다.
5. 각 장비에 대해 ‘설치됨 / 물리 장치 보임 / 프로그램이 연결함 / 사용할 준비 완료’를 별도로 기록한다.
6. COM 설정 읽기, USB 식별, Oasis Scan-only, Empire 상태는 가능 여부부터 확인한다. SDK open·센서 Connected 변경은 별도 장비 접근 단계다.

선택적으로 사용 가능한 읽기 조회 예시(이번 조사에서 실행하지 않음):

~~~powershell
$airaApiBase = 'http://localhost:1888/v2/api' # 실제 설정과 대조
$airaReadPaths = @(
  'version',
  'profile/show?active=true',
  'equipment/camera/info',
  'equipment/mount/info',
  'equipment/focuser/info',
  'equipment/guider/info',
  'equipment/switch/info'
)
foreach ($airaReadPath in $airaReadPaths) {
  try {
    $airaReply = Invoke-RestMethod -Uri "$airaApiBase/$airaReadPath" -TimeoutSec 5
    [pscustomobject]@{ Path=$airaReadPath; Reply=$airaReply }
  } catch {
    [pscustomobject]@{ Path=$airaReadPath; Error=$_.Exception.Message }
  }
}
~~~

Reply의 Success/Error/Response를 함께 검사한다. 연결되지 않은 장치의 조회가 오류를 내는 것은 가능하며, 이 예시는 연결을 시도하지 않는다. profile 응답에는 개인 경로/위치 등이 있으므로 전체를 공개 로그로 복사하지 않는다.

### 3차: 시뮬레이터 → 제한된 실장비 → 실제 하늘

- 시뮬레이터: 별도 프로필에서 연결/중단, 실패 응답, 순서·시간 경계, 정상 종료를 확인한다. 코드의 Simulate=true 시험과 NINA/PHD2 실제 프로그램의 시뮬레이터 시험은 별도로 표시한다.
- 제한된 실장비: 사용자와 시험 범위를 정한 뒤 카메라 한 장 저장·다운로드, 가이드 카메라 소유권 이전, 포커서 정상 범위 이동/취소, 정상 홈/정지를 검증한다.
- 실제 하늘: 극축 정렬, AF/솔빙 성공, 가이드 캘리브레이션과 안정화, 반전 후 센터링을 확인한다.
- 충돌·과부하·이동 중 케이블 분리·전원 차단 등은 실물에 일부러 만들지 않는다. 관련 실패 응답과 복구 제어는 F로 검증한다.
- 같은 장비를 클로드와 다른 도구가 동시에 조작하지 않는다. 시험 주체를 하나로 정한다.
- 기능 미지원 장비(냉각/로테이터/필터휠/돔 등)는 ‘미지원/미사용’으로 처리한다. 미래 확장 항목 때문에 현재 X-T5 구성을 막지 않는다.
